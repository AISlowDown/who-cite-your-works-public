# 作者职称与人才称号核验策略

## 纳入范围

- 默认只核验在引用论文中担任第一作者或通讯作者，且作者总被引次数严格大于 2,000 的作者。用户指定其他门槛时覆盖默认值；例如 `> 5,000` 只纳入 5,001 及以上，不将 5,000 本身纳入。
- 同一作者跨引用场景去重后按总被引次数降序排列，默认核验前 100 名。
- 只是普通共同作者的人不进入主报告或职称/人才称号检索；可在原始证据中留档。

## 身份消歧

姓名、引用论文署名机构、研究方向或个人标识（ORCID/OpenAlex/主页）至少有两项一致，才可把网页证据归到该作者。常见姓名、机构冲突或研究方向不符时标记 `身份冲突` 或 `待核验`，不得因为总被引数很高而强行匹配。

定向搜索先使用引号姓名加引用论文 affiliation；未命中时再依次叠加研究主题、引用论文精确题名、机构域名、ORCID 或论文通讯信息。中英文姓名、姓名顺序和缩写均可作为召回形式，但不能单独作为确认证据。

发现同名合并实体时，先保留所有候选身份及排除理由到证据 JSON，再只将与引用论文署名机构和研究方向匹配的身份写入展示层。不得因为一个 OpenAlex 实体被合并后超过被引门槛，就把该被引数归给引用论文中的同名作者。

### 私有覆盖记录

特定对象的官方主页覆盖记录使用外部 JSON，以稳定作者 ID 为键，可包含 `title`、`honor`、`sourceUrls`、`verifiedOn`、`matchMethod` 和 `notes`。`matchMethod` 应写明哪些身份信号与引用论文一致；不能只写“人工确认”。该 JSON 作为运行时输入传给通用脚本，不将真实人名和个案结论写入公开 skill。

### 引用论文署名机构的证据顺序

1. 出版商 HTML 中该篇引用论文的作者—机构编号与 affiliation 原文。
2. 出版商 PDF 首页、作者信息页或正式补充材料中的作者—机构对应关系。
3. 机构知识库保存的正式接收稿或出版社元数据。
4. OpenAlex、Crossref 等聚合平台的该论文 authorship 机构，仅在前三项不可取得时作为回退。

必须同时保存 affiliation 原文、规范化机构名、对应作者、来源 URL 和来源类型。论文原文与聚合平台冲突时以论文原文为准，并记录冲突；作者当前任职机构不得替代引用论文发表时的署名机构。论文署名机构可以用于身份消歧，但不能单独证明作者当前职称或人才称号。

## 字段口径

- `正式职称`：按最新可核验的官方机构主页原文记录，并给出中文规范译名。高校教师序列通常为教授、副教授、讲师、助教；研究序列通常为研究员、副研究员、助理研究员、研究实习员。
- `当前岗位/职务`：单独记录讲席教授、特聘教授、系主任、院长、实验室主任等岗位或行政职务，不把这些岗位自动折算为人才称号。
- `是否教授`：只有 Full Professor、Professor、Chair Professor 或国内正式“教授”记为“是”。副教授、助理教授、研究员、博士后和学生分别如实记录，不折算为教授。
- `青年科学基金项目A类（原国家杰青）`：2026 年采用现行名称，并可在括号中保留历史称谓；不得把普通国家自然科学基金项目写成 A 类或杰青。
- `青年科学基金项目B类（原优青）`：2026 年采用现行名称，并与优秀青年科学基金项目（海外）分列。
- `海外优青`：只认“优秀青年科学基金项目（海外）”或官方明确的“海外优青”表述；其他海外人才计划不等同。
- `长江学者`：区分特聘教授、讲座教授和青年学者，并记录项目原文与年份；学校自设“特聘教授”不自动等同长江学者。
- `院士`：中国科学院、中国工程院及其他国家/地区正式科学院或工程院的院士要写明院别；Fellow、会士、国家发明家科学院 Fellow 等不得笼统翻译为“院士”。
- `其他国家级领军人才`：记录国家特支计划科技创新领军人才、国家级领军人才等官网明确称号，不使用含糊的“大 title”代替原文。
- `其他国家级青年人才`：记录青年长江、青年拔尖等官网明确称号。
- `省部/地方人才`、`校级人才`：与国家级人才分列，校级“杰出教授”“青年学者”不能向上折算。
- `其他重要荣誉`：记录国务院政府特殊津贴专家、高被引科学家、IEEE Fellow 等；这些荣誉不等同于教授、国家人才称号或两院院士。
- 未在已核验官网简历中看到某项称号时写“官网未列示”，不要直接写“否”；没有完成身份匹配时写“待核验”。

## 证据优先级

1. 当前任职机构的正式个人主页或院系人员目录。
2. 国家自然科学基金委员会、中国科学院、中国工程院等授予机构的官方名单。
3. 作者 ORCID 或机构研究门户。
4. 出版商作者页、会议简介等仅作补充，不单独用于高风险人才称号认定。

每条已核验结果必须保存来源 URL、核验日期和备注。缓存已有且未过时的结论应直接复用；只有缺失、冲突或明确要求刷新时才重新联网查询。

## 院士与国际 Fellow 缓存顺序

1. 先读取引用论文中作者—机构对应关系，保存论文发表时机构。
2. 查询 `data/chinese-academicians-cache.json` 和 `data/international-fellows-cache.json`。
3. 用姓名召回候选，再比较论文机构、名单机构、当前官网机构、ORCID 和官方履历。
4. 机构相同标为 `verified_same_affiliation`；正常机构变更只有在官方履历加另一身份信号成立时标为 `verified_affiliation_change`。
5. 退休或荣休状态只作为官网自然提供时的可选补充信息，不要求为每位院士主动补全，也不作为作者、院士身份或 Honor 的排除条件。
6. `candidate_name_only`、`conflict`、`not_found_in_covered_cache` 不写入展示层 Honor。
7. 缓存没有覆盖、证据陈旧或发生冲突时才联网；新增记录必须回写组织官方 URL 和覆盖声明。

RSC 的 FRSC、IEEE Fellow 等专业学会等级按原名或规范中文“会士”展示，不得统一改写为科学院“院士”。多项已确认荣誉在一个单元格内用 ` • ` 分隔。
